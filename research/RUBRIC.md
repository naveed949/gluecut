# Frozen labeling rubric (gluecut v1)

**Status:** frozen for held-out eval. Do not silently relabel fixtures to chase scores.
**Version:** `rubric-v1` · **Freeze date:** 2026-10-21

If a case is ambiguous under this rubric, set `needs_human=true` (triage) or escalate (payments) rather than inventing a clever team/reason.

---

## Domain A — Support triage

### Label space

| Field | Values |
|-------|--------|
| `team` | `billing` \| `technical` \| `sales` |
| `priority` | `0`–`3` (integer score) |
| `needs_human` | `true` \| `false` |

### Team

| Label | Include | Exclude |
|-------|---------|---------|
| `billing` | refunds, invoices, charges, receipts, payment failures, unauthorized charges | pricing *questions* for new plans (→ sales) |
| `technical` | bugs, crashes, HTTP errors, outages, data-deletion *ops* when no legal team exists | sales demos |
| `sales` | demos, upgrades, plan/pricing questions, new business | existing-invoice ops |

**Multi-intent:** pick the **primary ask** as `team`, set `needs_human=true`.

### Priority

| Score | Meaning |
|------:|---------|
| 0 | Informational; can wait days |
| 1 | Normal queue; single-user non-blocking |
| 2 | Same-day; user/integration blocked or payment issue |
| 3 | Immediate; legal/fraud/security or widespread outage |

### Needs human

`true` when: multi-intent, legal/GDPR/lawyer, fraud, sarcasm+complaint mix, empty/no-signal, or otherwise unsafe to auto-route.
`false` when: clear single-team request with adequate signal.

### Split

- `fixtures/triage/dev.jsonl` — development / smoke (may include glue probes)
- `fixtures/triage/held_out.jsonl` — **≥100** scored cases for reporting (`rubric-v1`)

Glue probes may set `"eval": {"accuracy": false}`.

## Domain B — Payment failure → reason code

### Label space

| Field | Values |
|-------|--------|
| `reason` | `insufficient_funds` \| `fraud_suspected` \| `expired_card` \| `temporary` \| `other` |
| `auto_retry` | `true` \| `false` |
| `user_hint` | `try_another_card` \| `contact_bank` \| `try_later` \| `support` |

### Reason

| Label | Signals in prose |
|-------|------------------|
| `insufficient_funds` | NSF, not enough balance, declined for funds |
| `fraud_suspected` | unusual activity, suspected fraud, security hold |
| `expired_card` | card expired, expiration date |
| `temporary` | try again, issuer unavailable, timeout, network glitch |
| `other` | none of the above / unclear |

### Auto-retry

`true` only for `temporary`. Otherwise `false`.

### User hint

| Hint | When |
|------|------|
| `try_another_card` | funds / expired / clear method change |
| `contact_bank` | fraud / issuer block |
| `try_later` | temporary |
| `support` | other / unclear |

### Split

- `fixtures/payments/held_out.jsonl` — scored cases for second-domain proof

## Disagreement policy

A **disagreement** is when two engines differ on a primary label (`team` or `reason`) **or** one forced-wrong while the other did not.
Publish disagreements in `research/disagreements.md` (generated by `triage shadow`); do not resolve by quiet fixture edits—amend rubric version instead.
